# 청년정책 매칭 파이프라인

> 흩어진 청년정책을 매주 수집해, 내 조건에 맞는 것만 걸러 마감일·신청 링크와 함께 정리해 주는 개인용 데이터 파이프라인입니다.

|---|---|---|---|
| 2026.08 ~ | 1인 | 설계와 구현(AI 코딩 도구 활용) | Python, requests, BeautifulSoup, openpyxl, Claude API |

**수집 소스 2개 · 누적 정책 597건 추적(2026.09.30 기준) · 매주 월요일 오전 9시 자동 실행**

## 1. 문제 정의

- 청년정책이 온통청년, 청년몽땅정보통 등 여러 곳에 흩어져 있어 한 번에 보기 어렵습니다.
- 신청 기간이 며칠뿐인 정책도 있어, 가끔 확인하는 방식으로는 놓치기 쉽습니다.
- 결과를 보고 바로 신청할 수 있도록, **마감일과 신청 링크가 확인된 정책만** 결과에 올리는 것을 원칙으로 삼았습니다.

## 2. 아키텍처

```
수집 (온통청년 Open API, 청년몽땅정보통 게시판 HTML 파싱)
  ↓
공통 형식으로 표준화, 소스 간 중복 제거
  ↓
규칙 판정 (코드값 조건)
  ↓
AI 판정 (문장으로 적힌 조건)
  ↓
엑셀 출력 (매칭결과 · 확인필요 · 안내)
```

| 단계 | 모듈 | 내용 |
|---|---|---|
| 수집 | `api_client.py`, `seoul_youth_client.py` | 공식 API 호출(재시도 포함), 게시판 파싱(요청 간 1.5초 대기) |
| 표준화 | 각 클라이언트의 `normalize` | 소스마다 다른 응답을 정책명·마감일·링크·상태의 공통 형식으로 변환 |
| 중복 제거 | `dedup.py` | 제목 표기 차이를 정규화해 두 소스에 겹친 정책을 하나로 정리 |
| 규칙 판정 | `matcher.py` | 공식 코드정의서 기준으로 나이·지역·소득·학력·취업상태 등 판정 |
| AI 판정 | `llm_check.py` | 문장으로만 적힌 자격조건을 해당 / 제외 / 판단 불가로 판정 |
| 수집 이력 | `collector_state.py` | 소스별로 본 정책과 판정 결과를 저장, 증분 처리 |
| 출력 | `output_xlsx.py` | 매칭결과 / 확인필요 / 안내 시트로 저장 |

## 3. 핵심 설계 결정

### 1) 확정할 수 있는 조건은 AI에 맡기지 않는다
학력, 취업상태처럼 API가 코드값으로 주는 조건은 공식 코드정의서를 근거로 규칙으로 판정합니다. AI에는 "참여 제한 대상"처럼 문장으로만 적힌 조건의 판정만 맡겼습니다. AI는 확신이 없으면 반드시 "판단 불가"로 답하게 하고, 그 정책은 버리지 않고 사람이 확인하도록 남깁니다.

### 2) 불완전한 데이터는 버리지 않고 분리한다
마감일이나 신청 링크가 없는 정책은 "매칭결과"에 넣지 않고 "확인필요" 시트로 보냅니다. 상태(신청가능 · 신청예정 · 마감)로 이유를 구분해, 파싱 실패인지 아직 접수 전인지 알 수 있게 했습니다.

### 3) 이미 판정한 정책은 다시 판정하지 않는다
조건 문장이 지난 회차와 같으면 저장해 둔 판정 결과를 재사용해 AI 호출 비용을 줄였습니다.

### 4) 정상적인 0건과 수집 오류를 구분한다
소스가 정상적으로 0건을 돌려준 경우와 네트워크·파싱 오류를 구분해 "안내" 시트에 남깁니다. 소스 하나가 실패해도 나머지 소스는 계속 진행합니다.

## 4. 트러블슈팅

<details>
<summary>연도 없는 마감일을 잘못 추정해, 끝난 공고를 열린 공고로 표시한 문제</summary>

- **문제**: 게시판 제목에 "(~8/17)"처럼 연도 없이 날짜만 있어, 이미 지난 날짜를 내년 마감일로 추정하도록 처리했습니다.
- **원인**: 실제로는 오래 방치된 채 이미 끝난 공고가 많아, 끝난 공고가 내년 공고로 잘못 표시되었습니다.
- **해결**: 연도를 추정하지 않고, 확인할 수 없는 마감일은 "모름"으로 두어 확인필요 시트로 보냈습니다.
- **배운 점**: 추정이 틀렸을 때의 위험이 크면, 값을 지어내기보다 모른다고 드러내는 편이 안전합니다.
</details>

<details>
<summary>신청 기간이 수집 주기보다 짧은 정책을 놓치는 문제</summary>

- **문제**: 주 1회 수집인데, 신청 기간이 며칠뿐인 정책은 두 수집 사이에 열렸다 닫힐 수 있었습니다.
- **해결**: 아직 접수 전인 "신청예정" 정책까지 수집해 상태로 구분했습니다.
</details>

<details>
<summary>이미 본 정책이 결과에서 사라져 신청을 놓칠 수 있는 문제</summary>

- **문제**: 지난 회차와 상태가 같은 정책을 결과에서 빼는 기능이, 아직 신청하지 않은 정책까지 숨겼습니다.
- **해결**: 기본값을 끄고, "화면에 보여 줄 것"과 "다시 계산하지 않을 것"을 분리했습니다.
</details>

<details>
<summary>AI가 실제로는 판정에 성공했는데도 결과가 매번 "판단 불가"로 버려진 문제</summary>

- **문제**: 크레딧을 충전하고 API 호출이 정상적으로 되는데도, AI 판정 결과가 계속 판단 불가로만 나왔습니다.
- **원인**: 시스템 프롬프트로 "JSON 외의 다른 텍스트는 절대 붙이지 마라"고 지시했는데도, 모델이 응답을 마크다운 코드펜스(` ```json ... ``` `)로 감싸서 반환했습니다. 파싱 코드가 이를 그대로 `json.loads()`에 넣어서 매번 파싱 실패로 처리되고 있었습니다 — 즉 AI는 정상적으로 판정하고 있었는데, 그 결과를 코드가 계속 버리고 있었던 것입니다.
- **해결**: 파싱 전에 코드펜스를 벗겨내는 전처리를 추가했습니다.
- **배운 점**: 프롬프트로 출력 형식을 지시해도 모델이 어길 수 있으므로, 파싱 쪽에서 방어적으로 처리해야 합니다. 또한 "에러 없이 조용히 실패"하는 코드는 실제로 동작을 확인하기 전까지는 버그가 있어도 드러나지 않는다는 것을 체감했습니다 (하드 필터 결과만으로도 파이프라인이 "정상 동작"하는 것처럼 보였기 때문).
</details>

<details>
<summary>캐시된 "판정 실패" 결과가 영구 캐시로 오인돼 키를 연결해도 재판정이 안 되던 문제</summary>

- **문제**: API 키가 없어서 건너뛴 판정과, 호출은 했지만 실패한 판정이 모두 "이미 판정한 결과"로 캐시에 저장되고 있었습니다. 그래서 나중에 키를 연결해도 캐시만 재사용하고 실제 AI 호출은 영원히 일어나지 않았습니다.
- **해결**: 캐시된 결과의 사유가 "키 없음"/"호출 실패"로 시작하면 캐시로 인정하지 않고, LLM을 쓸 수 있을 때 다시 판정하도록 수정했습니다.
</details>

## 5. 운영

- **실행**: Windows 작업 스케줄러로 매주 월요일 오전 9시 자동 실행
- **실패 처리**: API 요청 실패 시 재시도(수집·AI 판정 모두), 오류는 소스 단위로 격리. 모든 소스가 실패하면 기존 결과 파일을 덮어쓰지 않고 종료
- **확인 지점**: 결과 엑셀의 "안내" 시트(소스별 수집 건수와 오류), `logs/run.log`
- **보안**: API 키와 개인 프로필은 `config.yaml`, `profile.xlsx`로 분리하고 `.gitignore`로 저장소에서 제외. 오류 메시지에 API 키가 노출되지 않도록 마스킹 처리
- **크롤링**: 공식 API가 없는 청년몽땅정보통만 파싱하며, 요청 사이에 간격을 두고 병렬 요청을 하지 않습니다.

## 6. 실행 방법

```bash
pip install -r requirements.txt
cp config.example.yaml config.yaml      # api.api_key에 온통청년 인증키 입력
python -m src.main --mock               # 키 없이 샘플 데이터로 동작 확인
python -m src.main                      # 실제 실행 → output/matched_policies.xlsx
python -m src.main --no-llm             # AI 판정 없이 규칙 판정만
```

AI 판정을 쓰려면 `config.yaml`의 `llm.api_key`(또는 환경 변수 `ANTHROPIC_API_KEY`)에 Anthropic API 키를 넣습니다. 없으면 에러 없이 건너뛰고 "판단 불가"로 표시합니다.

Windows에서는 `run_weekly.bat`을 작업 스케줄러에 등록해 매주 실행합니다.

테스트: `python -m tests.test_matcher` 등 `tests/` 아래 9개 테스트 모듈, 총 50개 테스트
